# [MEMBER 3] 完成并发上传去重事务和假锁恢复

## 当前缺口

第二阶段已实现 checksum 预约和真实 S3 直传，但尚未证明并发请求、失败上传和重试时的完整
一致性。

## 要求

- 条件事务同时创建 `CHECKSUM` 锁和 `MEDIA` 记录；
- 相同内容换文件名仍返回 409 和已有 `mediaId`；
- 预签名上传约束 content type、size 和 checksum metadata；
- 为未完成上传提供可恢复或过期策略，不能永久占用 checksum；
- 保证重试幂等，不产生重复媒体记录或对象。

## 验收

- 四个并发请求上传同一内容，只允许一个成功；
- 最终只有一个媒体记录、一个 checksum 锁和一个原文件；
- 覆盖事务冲突、上传中断和恢复路径的自动测试。
